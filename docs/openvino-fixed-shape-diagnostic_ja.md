# OpenVINO GPU固定shapeの出力差の調査

2026-09-15、i7-1195G7 / Iris Xe、GPUドライバ32.0.101.7088で確認。
Windows ML OpenVINO EPパッケージ1.8.84.0、EP DLL製品版1.6.1+d08e8e1。
GPUは既存のFP32 / ACCURACY設定。RMVPEのCPU回避策は維持した。

## 結論

今回のRVC固定shapeでの大きな音声差は、相対位置Attention内の
**Slice → MatMulの組み合わせが、OpenVINO GPUの固定shape経路で誤った値を返すこと**に起因する。
CPUでは固定shapeでも再現せず、GPUの動的shapeでも再現しない。
人工データだけの2演算モデルでも再現したため、GPUの処理速度不足やRVCの学習済み重み、
マイク入力、RMVPE、チャンク結合を原因とする説明ではない。

OpenVINO GPUコンパイラ、演算実装、ドライバのどの内部処理が誤っているかまでは未特定。
切り出したテンソルのレイアウト・オフセットの扱いや後続演算との最適化が疑われるが、
具体的なカーネルやコード行の特定はしていない。他のGPU・ドライバ・EP版には一般化しない。

## 切り分け

RVC単体へ同じ特徴量・pitch・pitchf・話者・rnd・nsf_noise・phase_inを与えた。
62フレーム、48 kHz、160 Hz / 220 Hzの2条件。各バックエンドの音声と位相を保存して比較した。

- CPUの動的／固定shapeは音声がほぼ一致し、NSF位相は一致。
- GPU動的shapeもCPUに近い値。
- GPU固定shapeは160 Hz条件の音声相対RMS差が約99.4%。
- この条件のNSF位相の最大円周誤差は約0.0000193周期。大きな音声差は位相だけでは説明できない。
- 中間出力を順に追加すると、入力の線形変換・最初のQ/K/V投影・Attention重みはCPUと近い。
- 最初に大きく異なる箇所は、相対位置Attentionの`rel_values_250`。
  入力は`rel_weights_182` `[1,2,62,123]` と `relv_emb_unsqueezed_252` `[1,1,123,96]`。
  前者はCPUと近く、後者は完全一致。それぞれGPUから取り出した入力をNumPyで再計算しても、
  GPU固定shapeのMatMul出力と一致しない。最大絶対差は約0.990。
- MatMul単独の人工モデルは正常。前段のPad・Reshape・Sliceを付けると再現し、
  最終的にSliceとMatMulだけの2演算まで縮小できた。

## 最小再現

人工乱数のみを使い、RVCモデルの重みを含まない。

```text
A: float32 [1, 2, rows, 124]
B: float32定数 [1, 1, 123, 96]
S = Slice(A, starts=[1], ends=[124], axes=[3], steps=[1])
Y = MatMul(S, B)
```

実入力はrows=62。固定条件はORT `with_dimension_override("rows", 62)`。
NumPyの`A[:, :, :, 1:] @ B`を基準とした結果:

| 経路 | 最大絶対差 | 相対RMS差 |
|---|---:|---:|
| ORT CPU 動的 | 0 | 0 |
| ORT CPU 固定 | 0 | 0 |
| OpenVINO GPU 動的 | 0.00001335 | 0.0000002075 |
| OpenVINO GPU 固定 | 29.258 | 0.8862 |

Sliceを等価な`Gather(A, indices=1..123, axis=3)`へ置き換えると、
GPU固定でも最大絶対差0.00001335、相対RMS差0.0000002075へ戻った。
形を2次元へ変更するReshapeの追加だけでは、実モデルの不一致は解消しなかった。
前回の調査ではORTグラフ最適化を無効化しても解消しなかった。

## 実モデルの回避策の検証

診断用ONNXコピーに対し、相対位置Attentionの6箇所の`rel_weights_*`を生成するSliceを、
同じ添字を生成するRangeとGatherへ置換した。元ONNXは変更していない。
添字の終端は元の動的長から計算し、モデルを62フレーム専用の固定値で書き換えてはいない。

160 Hz条件のRVC単体の音声相対RMS差は、CPU基準に対して約99.4%から約0.0272%へ縮小。
220 Hzでは約71.4%から約0.0153%へ縮小した。残るNSF位相等の微小な差まで解消したわけではない。

同じ60秒テスト信号を、RVCのみ固定shape、ContentVecは動的、RMVPEはCPUで変換した結果:

| 指標 | 結果 |
|---|---:|
| 定常チャンク数（初期3チャンクを除外） | 117 |
| 平均処理時間 | 225.41 ms |
| p95 / p99 | 253.18 / 310.29 ms |
| 最大 | 343.51 ms |
| 500 ms超過 | 0/117 |
| 動的GPU基準との相対RMS差 | 0.0003481（約0.0348%） |
| 同・相関 | 0.99999994 |
| 同・最大絶対差 / LSD | 0.001678 / 0.9237 dB |

大きな不一致を抑えつつ高速化を維持できた。ただし比較ツールの最大絶対差・LSDの既定閾値には
不合格であり、厳密一致・音質検証合格とは扱わない。ORT CPU基準との相対RMS差は約0.347%、
従来の動的GPU対CPUの約0.353%と近い。
性能測定は1回・1モデル・人工信号であり、温度・電力・周辺負荷は統制していない。
実音声の聴感、他モデル、他チャンク長、GUI/VST3の実時間動作は未検証。

## 保存物と適用範囲

ローカル`target/openvino-fixed-cause/`に以下を保存した。

- `slice/`: 人工データのみの2演算再現ONNX、入力、NumPy基準出力、実行ログ、各バックエンド出力。
- `gather/`: 等価なGatherへの置換による回避検証。
- `make_slice.py` / `make_gather.py` / `onnx_wire.py` / `make_matmul.py`: 再現モデル生成コード。
- `diagnostic-sessions.rs`: 診断時のテストコードを含むソース。
  `fixed_shape_matmul_repro`は`VC_RS_DIAG_MODEL`・`VC_RS_DIAG_OUTPUT`を指定して実行した。
  終了成功はデータ取得の成功であり、数値比較合格を意味しない。
- `minimal-summary.json`: 最小モデルの数値比較。
- `checkpoints/` / `attention/` / `relative-values/`: 実モデル内部の切り分けデータ。
- `replace_relative_slice.py` / `gather-rvc.onnx`: 実モデルの診断用変換と派生モデル。
- `gather-wav/`: 60秒変換結果、統計、比較結果、実際のEP情報・ドライバ・ハッシュ。

診断用コードは通常ソースから撤去し、復元をハッシュで確認。
通常CLIのバイナリ・通常モデル・既定設定は変更していない。実験用バイナリでのみ回避策を検証した。
製品へ反映する際は、対象パターンの厳密な検出、等価性の回帰テスト、派生モデル管理、
固定shapeのロード・設定変更時の整合性確認を行う。単純なノード名置換を汎用処理として採用しない。
